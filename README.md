# Парсер туров из российских городов

CLI сравнивает пакетные туры из выбранного российского города в выбранную страну, склеивает дубли, рассчитывает выгодность от 0 до 100 и создаёт консольный, HTML, Excel и CSV-отчёты. Реализовано **11 адаптеров**: Travelata, Слетать.ру, TEZ TOUR, Tourvisor, Biblio-Globus, Level.Travel, Tourtrans, ПАКС, Ambotis, Русский Экспресс и Space Travel. Наличие адаптера не означает, что оператор уже выдал доступ: без партнёрских ключей/фидов можно использовать TEZ TOUR и Tourtrans. Используются API и выгрузки, без обхода авторизации или антибот-защиты.

## Установка

Требуется Python 3.11+.

```bash
python -m venv .venv
source .venv/Scripts/activate  # Git Bash Windows
python -m pip install -r requirements.txt
```

Для PowerShell активация: `.venv\Scripts\Activate.ps1`.

Playwright нужен только новым адаптерам динамических HTML-сайтов. Встроенные JSON-адаптеры браузер не запускают. Для таких адаптеров один раз выполните:

```bash
playwright install chromium
```

## Доступы к источникам

- **Travelata**: получите доступ к партнёрскому API через Travelpayouts. Задайте `TRAVELATA_API_USERNAME` и `TRAVELATA_API_PASSWORD`; используется HTTP Basic Auth.
- **Слетать.ру**: запросите у сервиса логин и пароль JSON-шлюза. Задайте `SLETAT_API_LOGIN` и `SLETAT_API_PASSWORD`.
- **TEZ TOUR**: публичный JSON-шлюз поиска; в опубликованной документации указан лимит 50 запросов в минуту с одного IP. Авторизация в документации метода не требуется.
- **Tourvisor**: платный XML/JSON-шлюз для турагентств. Задайте `TOURVISOR_API_LOGIN` и `TOURVISOR_API_PASSWORD`.
- **Biblio-Globus**: агентский JSON API. Задайте `BIBLIO_GLOBUS_LOGIN` и `BIBLIO_GLOBUS_PASSWORD`; адаптер выполняет form-логин и обновляет cookies `A1`, `Z1`, `L` через HTTP-сессию.
- **Level.Travel**: запросите у партнёрской команды URL YML-фида для города вылета и задайте `LEVEL_TRAVEL_FEED_URL`. Фид содержит только предложения на двоих, 7–14 ночей и ближайший месяц; остальные запросы адаптер пропускает.
- **Tourtrans**: открытая ежедневная XML-выгрузка `https://www.tourtrans.ru/tours.xml`. Адаптер выбирает туры с подтверждённым в тексте городом вылета, добавляет авиадоплату к базовой цене и не рассчитывает детские тарифы. Это ежедневный снимок, а не live-актуализация.

Git Bash:

```bash
export TRAVELATA_API_USERNAME="логин"
export TRAVELATA_API_PASSWORD="пароль"
export SLETAT_API_LOGIN="логин"
export SLETAT_API_PASSWORD="пароль"
export TOURVISOR_API_LOGIN="логин"
export TOURVISOR_API_PASSWORD="пароль"
export BIBLIO_GLOBUS_LOGIN="логин"
export BIBLIO_GLOBUS_PASSWORD="пароль"
export LEVEL_TRAVEL_FEED_URL="https://адрес-выданного-городского-фида"
```

PowerShell использует `$env:TRAVELATA_API_USERNAME="логин"` и аналогично для остальных. Секреты не записывайте в YAML. Если учётных данных нет, отключите источник в `config.yaml` или не передавайте его в `--sources`; ошибка одного источника не останавливает остальные.

### Дополнительные операторы САМО-тур

| Оператор | Имя для `--sources` | Переменная окружения | Портал |
|---|---|---|---|
| ПАКС | `paks` | `PAKS_API_TOKEN` | https://newonline.paks.ru |
| Ambotis Holidays | `ambotis` | `AMBOTIS_API_TOKEN` | https://online.ambotis.ru |
| Русский Экспресс | `russian_express` | `RUSSIAN_EXPRESS_API_TOKEN` | https://online.r-express.ru |
| Space Travel | `space_travel` | `SPACE_TRAVEL_API_TOKEN` | https://online.space-travel.ru |

Нужен отдельный `oauth_token` для API каждого оператора, полученный по договору. Пароль агентского кабинета его не заменяет; оператор может дополнительно ограничивать доступ по IP. Не используйте чужие ключи или токены из JavaScript страниц.

```bash
export PAKS_API_TOKEN="ключ, выданный ПАКС"
export AMBOTIS_API_TOKEN="ключ, выданный Ambotis"
export RUSSIAN_EXPRESS_API_TOKEN="ключ, выданный Русским Экспрессом"
export SPACE_TRAVEL_API_TOKEN="ключ, выданный Space Travel"
python main.py --sources paks,ambotis,russian_express,space_travel \
  --from "Москва" --to "Турция" --date-from 2027-06-01 --date-to 2027-06-07 \
  --nights 7-10 --adults 2 --children-ages 9 --stars 4-5 --meal AI
```

Общий протокол реализован в `scrapers/_samo.py`, а у каждого оператора отдельный файл, адрес и имя переменной окружения. Ключ передаётся в теле POST, не в URL; в SQLite ключ запроса хранится как SHA-256. Используются `SearchTour_TOWNFROMS`, `SearchTour_STATES`, `SearchTour_CURRENCIES`, `SearchTour_PRICES`. Справочники разрешают имена городов/стран без зашитых числовых ID. Даты передаются как `YYYYMMDD`, возрасты детей — через `AGES`, до трёх детей.

Возвращаются только доступные полные авиапакеты (`packetType=0`, `transportCodeKey=1`), для нужного маршрута и состава туристов. Переездные туры и проживание в нескольких отелях исключаются. Рублёвая цена берётся из ответа оператора, не из примерного валютного курса. Неизвестные рейтинг, багаж, страховка, трансфер и точное время рейса остаются неизвестными; при фильтре `--min-rating` такие предложения не проходят. Ссылка ведёт на форму конкретного предложения `bron?CATCLAIM=...`; для просмотра может понадобиться агентский вход. Парсер не создаёт заявки и ничего не бронирует.

Поиск разбит на диапазоны `date_chunk_days` и `nights_chunk_size`. `max_pages` ограничивает число страниц каждого диапазона/группы; достижение лимита отмечается в логе как неполная выборка. `max_requests` ограничивает все вызовы адаптера за запуск: при превышении источник завершается с явной ошибкой. Коды API 101/102/105 означают необходимость уменьшить диапазоны. Ошибка авторизации или изменение схемы не выдаются за отсутствие туров.

**Проверка 2026-11-05:** все четыре адреса API ответили HTTP 401 с `apiKey not provided` на запрос без токена. Это подтверждает наличие защищённого интерфейса, но не проверяет получение цен: партнёрских ключей в этой сессии не было. Контрактные тесты используют явно помеченную синтетическую фикстуру по документации САМО, а не якобы живые ответы операторов.

## Запуск

```bash
python main.py --from "Москва" --to "Турция" --date-from 2026-06-01 --date-to 2026-06-15 --nights 7-10 --adults 2 --stars 4-5 --meal AI
```

Дополнительные параметры:

```bash
python main.py --from "Санкт-Петербург" --to "ОАЭ" \
  --date-from 2027-01-10 --date-to 2027-01-25 --nights 5-9 \
  --adults 2 --children-ages 4,9 --stars 4-5 --min-rating 8 \
  --budget 350000 --sources tez_tour,travelata --sort price --top 20
```

Без аргументов используются значения секции `search` из `config.yaml`. `--sort value` сортирует по скорингу, `--sort price` — по цене на человека. Отчёты сохраняются в `reports/`, база — в `data/tours.db`, лог — в `logs/parser.log`.

### Выгодность и история

Веса факторов настраиваются в `scoring.weights`. Учитываются цена на человека за ночь относительно средней и медианы, звёзды и рейтинг, питание, багаж/трансфер/страховка, прямой перелёт и время вылета, а также отклонение от медианы похожих отелей (звёзды + питание). Неизвестные характеристики получают нейтральную оценку, а не штраф.

При первом запуске отметок о снижении цены нет. При следующих запусках SQLite сравнивает текущую минимальную цену того же нормализованного тура с предыдущим наблюдением. Ответы API кэшируются 90 минут; для отключения чтения кэша установите `cache_ttl_seconds: 0`.

API запрашивают цены в RUB. Если источник вернул другую валюту, применяется резервный курс из `currency.rub_rates`; актуализируйте его в конфиге.

## HTML и табличные отчёты

HTML не загружает внешние библиотеки: CSS, JavaScript и SVG-гистограмма встроены в файл. Верхние карточки содержат прямые ссылки, полная таблица поддерживает сортировку по столбцам, поиск по отелю/курорту и фильтры по звёздам, питанию и максимальной цене. XLSX содержит фильтр и закреплённый заголовок, CSV записывается в UTF-8 с BOM для Excel.

## Добавление нового сайта

1. Проверьте условия использования, robots.txt и наличие официального JSON API. Предпочитайте API HTML-парсингу.
2. Создайте `scrapers/my_source.py` и класс `MySourceScraper(BaseScraper)` с уникальным `name` и реализацией `async search(params) -> list[Tour]`.
3. Используйте `self.client.get_json/post_json`: там уже реализованы robots.txt, случайные задержки, ограничение параллелизма, retry, кэш и обработка блокировок. Для динамического HTML доступен `BrowserClient` из `scrapers/browser.py` и BeautifulSoup; он всегда проверяет robots.txt.
4. Преобразуйте ответ через `self.make_tour(...)`, чтобы цена и цена на человека были в RUB. Вынесите endpoint, поля и селекторы в константы адаптера.
5. Добавьте секцию источника в `config.yaml` и тест на реальном сохранённом JSON/HTML fixture. Регистрировать класс вручную не нужно: `discover_scrapers()` находит его автоматически.

## Этичность и ограничения

Соблюдайте robots.txt, условия API/сайта, ограничения частоты и лицензии на данные. Проект не обходит CAPTCHA, авторизацию или антибот-защиту. HTTP 401/403/429 и запрет robots.txt считаются сигналом остановить запросы к источнику. Не увеличивайте параллелизм и не уменьшайте задержки для обхода лимитов. Цены могут измениться до бронирования — проверяйте их на странице оператора.

В HTTP-клиенте проверка robots.txt включена по умолчанию. Новые четыре адаптера САМО всегда запрашивают эту проверку; не отключайте глобальный `network.respect_robots_txt`. У Space Travel опубликован `Crawl-delay: 10`: клиент соблюдает его, даже если в YAML стоят задержки 1–3 секунды. Проверяется полный URL с параметрами и доступ к кэшированному ответу; учитывается также `Request-rate`.

У ранее добавленных партнёрских API в конфигурации сохранено `check_robots_txt: false`. Это не разрешение на сбор данных: используйте их только в пределах условий выданного доступа; для проверки robots.txt задайте `true` в соответствующей секции. HTTP 401/403 не обходится.

## Что может сломаться и как чинить

- **Новая версия или поля API**: сравните ответ с fixture, обновите endpoint/константы индексов в соответствующем файле `scrapers/`, затем запустите тесты. Не меняйте общий CLI.
- **Изменилась вёрстка динамического источника**: обновите селекторы в его адаптере, сохраните новый HTML fixture и проверьте, что robots.txt по-прежнему разрешает путь.
- **401/403**: проверьте срок и права учётных данных и условия доступа. Не подменяйте защиту и не пытайтесь её обойти.
- **429/тайм-ауты**: увеличьте задержку и тайм-аут, уменьшите `max_concurrency`, сохраните экспоненциальный retry. При `Retry-After` клиент ждёт указанное время.
- **CAPTCHA/антибот**: источник считается недоступным; используйте официальный API или запросите разрешение владельца.
- **Дубли не склеиваются**: проверьте `normalize_hotel_name()` и порог `fuzzy_threshold`; слишком низкий порог может объединять разные отели.
- **Нет отметок о снижении цены**: нужен предыдущий запуск с тем же отелем, датой, длительностью, питанием, городом и страной; изменение этих параметров создаёт другую историю.
